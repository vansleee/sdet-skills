# Setup SDET

一次問一個主題訪談使用者，把答案寫進 `config/`。可重複執行：先讀現有 config，只問缺的。設計理念見 `docs/foundation/setup-sdet.md`。

## 鐵律
- 祕密不落地：帳密/token 只記變數名（`env:VAR`），不記值，不在對話裡索取。
- 寫檔前先列給使用者確認。
- 一次一個主題。

## 產出
    config/product-context.md          # 產品、環境、登入、Playwright、trace 來源
    config/ci-backend-github-actions.md
    config/issue-tracker-github.md
    config/sdet-config.yaml             # confidence / dedup / budget / models / risk

## 訪談 → 寫入
1. 受測產品：各環境 base URL、一句話說明 → product-context.md。
2. 登入：storageState 路徑、帳密來源 `env:VAR`（確認 `.env` 已 gitignore）→ product-context.md。
3. CI（GitHub Actions）：確認 `gh auth status`、repo；哪個 workflow 產 Playwright artifact。指令寫進 ci-backend-github-actions.md（`gh run view --log-failed`、`gh api .../jobs`、`gh run download`）；一律用 `gh`。
4. Issue tracker（GitHub Issues）：issue repo、triage label；canonical→實際 label 對應寫進 issue-tracker-github.md；AI 留言開頭加 `> *This was generated by AI during triage.*`。
5. Playwright：config / testDir / reporter 路徑；確認 trace / screenshot / video 已開 → product-context.md。
5b. Trace 能力（MCP 現場探索）：工具集無 `browser_start_tracing` → 提示加 `--caps=devtools`（`claude mcp add ... -- npx @playwright/mcp@latest --caps=devtools --output-dir ./.pw-mcp-traces`）；暫存 output-dir 記進 product-context.md。
6. 門檻 → sdet-config.yaml：`confidence.min_to_file`、`dedupe`、`budget`、`models`（cheap/strong）、`risk.weights`。

## 收尾
印出摘要（各 config 寫了什麼、哪些祕密需使用者自設 env）、提示下一步 `/exploration-charter` 或 `/triage`；必填缺漏（如 gh 未登入）列出請補後重跑。
