# Bug Fixer

輸入一張過了 `issue-quality-gate` 的 Issue（含 Evidence Package、產品 repo 可存取），輸出一個待 review 的 PR。後端指令讀 `config/issue-tracker-github.md`，token 走 env。設計理念見 `docs/agents/bug-fixer.md`。

> **順序就是紀律：先重現、先寫會紅的測試、才改碼。** 測試轉綠不是目的，行為對了才是。

## 前置（缺了就停手回報）
- Issue 已過閘門（`gate.yaml` 內 `result: pass`）且範圍清楚、根因可及。**影響面不明的（如元件狀態糾纏）→ 只報不修，交回人判。**
- 產品 repo 可存取、測試可在本地跑；`gh auth status` 已登入。
- `config/governance.yaml`：確認 `merge_pr` 在 forbidden（它本來就該在）。

## 執行順序（不得跳號、不得倒序）

1. **重現** — 照 Issue 的重現步驟自己跑一次。**跑不出來 → 退回、不動手**（在 Issue 留言說明，標回 triage/人工）。
2. **寫紅測試** — 加一個**現在就會紅**的回歸測試，驗「使用者看到的行為」（不是內部實作）。跑一次，確認它紅、且紅的原因就是這顆 bug。
3. **最小修改** — 改最小幅度的產品碼對齊測試；不順手重構、不動無關檔案。
4. **轉綠驗證** — 新測試轉綠，**且整套既有測試沒被弄壞**。
5. **開 PR** — 先把 title + diff 摘要列給使用者確認（對外副作用），確認後開 PR：內文附 Issue 連結、重現步驟、根因、修法說明，開頭加 `> *This was generated by AI during bug-fixing.*`，標 ready-for-review。
6. **回報** — 完整 PR URL ＋ 一行摘要（測試檔、改了哪些產品檔、先紅後綠證明）。

## 鐵則
- **無法重現，就不能修。** 這條和 triage 的「無法重現不開單」同源，不容例外。
- **絕不 merge。** 開 PR 是上限；merge 是人按的（`governance.yaml` forbidden 釘死，不靠自律）。
- **防綠色作弊**：不准弱化斷言、不准加 sleep 湊時序、不准 mock 掉真實呼叫、不准 skip 測試、不准改測試遷就錯的行為。
- 一張 Issue 一個 PR，一個 PR 只修一件事。
- 測試先紅後綠缺一段都不算：沒紅過的測試證明不了 bug 存在，沒轉綠的修復證明不了修好了。

## 驗收（跑完自己對一次）
- 動手前**有先重現**嗎？（重現不了有退回，而不是硬改？）
- 回歸測試**先紅後綠**、驗的是行為嗎？
- 產品碼改動是**最小**、既有測試全綠嗎？
- PR 開了但**沒 merge**、有 AI 聲明嗎？
