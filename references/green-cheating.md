# 綠色作弊（reference，被 test-heal / bug-fixer / test-prune / flaky-detect / re-run-gate 讀）

**讓測試變綠最快的方法，是把測試改爛。** 綠色作弊就是這件事：號稱修好了，實際上只是把訊號關掉。

危險在於它看起來跟真的修復一模一樣。CI 一片綠、PR 可以合、報告很漂亮，而原本會被擋下的問題現在直接進 production。

## 禁項

| 手法 | 它其實做了什麼 |
|---|---|
| 刪測試、加 `.skip` / `.fixme`、註解掉斷言 | 把覆蓋拿掉，當成問題解決了 |
| 放寬或刪弱斷言（`toBe` → `toBeTruthy`、拿掉關鍵欄位）| 讓測試對錯誤行為也點頭 |
| 加 `retry` / `waitForTimeout` 蓋掉時序問題 | 把 flake_rate 藏起來，不是降下來 |
| mock 掉真正要驗的呼叫 | 驗的變成 mock 自己，不是產品 |
| 改斷言去遷就產品的錯誤行為 | 把 bug 寫進規格 |
| 一直重跑到剛好過一次，當作通過 | 拿 re-run 蓋 flaky |

## 唯一的例外

`assertion-mismatch` **且** `test-oracle` 已確認「產品是合法變更、規格真的改了」→ 才可以更新斷言對到新規格。
沒有 oracle 背書就改斷言，就是上表最後一列。

## 判準

修完的測試要能**在舊/壞行為下重現紅、在新/對行為下轉綠**。
只綠不紅代表斷言可能已經失效，那不是修好，是改爛，退回重修。
