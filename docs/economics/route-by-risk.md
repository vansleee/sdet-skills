# Route by Risk
用風險決定要不要測、先測什麼,放在 pipeline 最前面當閘門。

## 設計理念
- **不是所有東西都值得測。** token、時間都有限，把它們平均灑在高風險與低風險的角落上，等於把資源從真正重要的地方偷走。
- **放最前面，因為它決定範圍，不決定做法。** 先回答「這輪值不值得花力氣」，再輪到 `explore` / `ci-pipeline` 決定怎麼做；順序反過來，就會先跑再問值不值得，money already spent。
- **三個因子夠用，不需要更多。** change_frequency（常改）、user_traffic（常用）、past_failures（常壞）分別對應「最可能又壞」「壞了影響最大」「歷史上真的壞過」；再加因子邊際收益低，先求可解釋。
- **缺資料用中性值，不用零。** 「沒人量過」跟「量過確定沒風險」是兩件事；把缺資料當零風險，等於用資料缺口懲罰那些沒人關注過的角落——它們往往正是最該關注的。
- **skip 要留痕。** 風險路由做錯最貴的代價，是漏掉一塊沒人發現。留痕才讓「這塊為什麼沒測」變成可回答的問題，而不是消失在紀錄之外。
- **和 sdet-economics 分工不重疊。** 本 skill 回答「要不要測」；`sdet-economics` 回答「用什麼成本測」。兩個問題分開問，才不會用成本壓力偷偷影響風險判斷（反之亦然）。
