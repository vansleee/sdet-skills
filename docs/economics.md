# economics/

`skills/economics/` 每支 skill 的設計理由。執行指令在各自的 `SKILL.md`，這裡只寫為什麼。

## route-by-risk

用風險決定要不要測、先測什麼，放在 pipeline 最前面當閘門。

### 設計理念
- **不是所有東西都值得測。** token、時間都有限，把它們平均灑在高風險與低風險的角落上，等於把資源從真正重要的地方偷走。
- **放最前面，因為它決定範圍，不決定做法。** 先回答「這輪值不值得花力氣」，再輪到 `explore` / `ci-pipeline` 決定怎麼做；順序反過來，就會先跑再問值不值得，money already spent。
- **三個因子夠用，不需要更多。** change_frequency（常改）、user_traffic（常用）、past_failures（常壞）分別對應「最可能又壞」「壞了影響最大」「歷史上真的壞過」；再加因子邊際收益低，先求可解釋。
- **缺資料用中性值，不用零。** 「沒人量過」跟「量過確定沒風險」是兩件事；把缺資料當零風險，等於用資料缺口懲罰那些沒人關注過的角落。它們往往正是最該關注的。
- **skip 要留痕。** 風險路由做錯最貴的代價，是漏掉一塊沒人發現。留痕才讓「這塊為什麼沒測」變成可回答的問題，而不是消失在紀錄之外。
- **和 sdet-economics 分工不重疊。** 本 skill 回答「要不要測」；`sdet-economics` 回答「用什麼成本測」。兩個問題分開問，才不會用成本壓力偷偷影響風險判斷（反之亦然）。

## sdet-economics

校準改以 project、session、finding_id 定位預測，verifier 重現結果與 human 裁定分開。人工 precision 只計已明確裁定的樣本；獨立重現率另計，null／inconclusive 不視為否定。欄位與舊資料處理見 `references/confidence.md`。

成本紀律 reference：省 token、重用 context、模型分級、預算與停止條件、ROI、績效。

### 設計理念

- **agent 不會自己喊停。** 沒有寫死的預算與停止條件，探索型 agent 傾向一路挖下去；停止條件必須是規則，不是臨場感覺。
- **模型分級省的不是小錢，而是把貴模型留給值得判斷力的那一步。** 大量掃描用便宜模型划算；但判定步驟（是不是 bug、能不能開單）判錯的代價遠高於模型差價，不准為了省錢降級。
- **沒有 calibration 就沒有 ROI，沒有 ROI 就無法幫 agent 說話。** 之後要跟人解釋「這個 agent 值不值得放權跑」，靠的是這裡的資料，不是印象；今天不記，之後補不回來。
- **ROI 的分母只能是 confirmed，不能是 findings。** 候選發現量大不代表有價值，算 ROI 時把未驗證的也算進去，會製造好看但騙人的數字。
- **停在哪、為什麼停，跟結果一樣重要。** 一次沒跑完的探索，若不記錄停止原因，下次沒有人知道是該加預算、還是那塊真的不值得投入更多。
- **和 route-by-risk 分工不重疊。** `route-by-risk` 決定要不要測；本文件決定測的時候怎麼花、花完值不值得。兩層治理疊起來，才不會一邊為了風險猛測、一邊燒穿預算沒人喊停。
