# Test Data

讓每支測試自己準備、自己清掉它要的資料。

## 設計理念
- **「環境裡本來就有那筆資料」是慢性病。** 它平常都對，直到有人改了那筆資料、或兩支測試同時用它。這種紅最難查，因為程式碼沒動。所以規則直接下在源頭：不依賴既有資料、不共用可變狀態。
- **走 API 建資料，不走 UI。** 用 UI 建前置資料等於把別的功能綁進這支測試的失敗面。登入頁改版，結帳測試跟著紅。API 快、穩，而且失敗訊息指得準。
- **唯一標記是為了平行。** 時間戳＋亂數讓多個 worker 不會搶同一筆，也讓事後在共享環境裡認得出「這是誰建的」。
- **清理放 teardown 而不是測試最後一行。** 測試紅了就跑不到最後一行，於是殘留資料變成下一支的 flaky。失敗會傳染，這是傳染路徑之一。
- **清理失敗要大聲。** 靜默吞掉等於把問題推給下一個人，而且推的時候沒留痕跡。
- **不碰共享環境的核彈鈕。** `reset_shared_env`、`truncate_shared_db` 在 governance 屬 forbidden：它們確實能「清乾淨」，代價是把別人的工作一起清掉。清理只清自己建的東西，這條沒有例外。
- **邊界。** 只提供資料；測試碼要修交 `test-heal`，間歇紅的定性交 `flaky-detect`。
